# GROK.md — встановлення розсилки помічником Grok

Ти встановлюєш автоматичну розсилку оголошень у Telegram-групи для людини, яка
**не програміст**. Усе в цьому файлі — для тебе. Людині кажи тільки те, що їй треба
зробити самій, простими словами, по одному кроку.

Це **єдиний** сценарій встановлення для помічника. Не виконуй `setup.sh` (він читає
`/dev/tty`, а в тебе немає термінала). Не йди за `SETUP.md`, `MASTER.md` чи
`CLAUDE-CODE.md`: перший лише перенаправляє сюди, решта — для людини.
Майстер `setup.sh` лишається для того, хто сидить у терміналі на сервері сам.

Комплект працює на **сервері учня** (Ubuntu 22.04 або 24.04, користувач root),
у каталозі `/root/broadcast`. Твій комп'ютер можуть замінити. На ньому не живе
ні сесія Telegram, ні `.env`, ні розклад. Клон репозиторію в тебе — тільки щоб
читати цю інструкцію.

## Кілька акаунтів на одному сервері

Усі акаунти учня працюють на **одному** сервері, кожен у своїй папці: перший —
`/root/broadcast`, другий — `/root/broadcast-2`, третій — `/root/broadcast-3` і так далі.
У кожній папці свій `.env`, свій вхід, свої тексти й свій розклад; папки одна одній не заважають,
а прогони рознесені в часі самим комплектом. Другий сервер під другий акаунт не потрібен.

Щойно підключився до сервера (розділ нижче), подивись, які акаунти вже стоять. Ця ж команда
оновлює комплект у всіх папках — старий код не знав про сусідні папки:

```bash
vps 'for d in /root/broadcast /root/broadcast-[0-9]*; do [ -f "$d/.env" ] || continue; echo "== $d"; { git -C "$d" fetch -q origin main && git -C "$d" reset -q --hard origin/main; } || echo "UPDATE_FAILED $d"; (cd "$d" && bash install.sh --status | grep -E "^(session|join_cron|join_complete|broadcast_cron)="); done; true'
```

- Є рядок `UPDATE_FAILED` — **не додавай** новий акаунт, доки оновлення не пройде (повтори команду
  за хвилину; інтернет на сервері). Старий код у сусідній папці зітре розклад нового акаунта.
- Учень **встановлює** розсилку і підключає **три акаунти** (прийшов зі сповіщенням ⛔️/⚠️ чи з питанням —
  спершу таблиці внизу, нового акаунта не починай). Порядок: спершу доведи до кінця акаунт, у якого `join_cron=no` і
  `broadcast_cron=0` (почали, але не закінчили). Якщо таких нема і готових акаунтів менше трьох — одразу
  переходь до наступного: скажи учню «Тепер підключаємо акаунт N з 3» і що для нього підготувати
  (окремий акаунт з Premium, хмарним паролем і @username, його власні api_id і api_hash). Не питай,
  чи хоче він далі, — просто веди; якщо учень сам каже «потім», зупинись.
- Новий акаунт — бери наступний вільний номер (є лише `/root/broadcast` → нова папка
  `/root/broadcast-2`) і виконуй цей файл від кроку 2 до кінця **для цієї папки:
  у кожній команді заміни `/root/broadcast` на неї** (`cd /root/broadcast`, шляхи до файлів,
  рядок `join_step.sh` у розкладі). У папках інших акаунтів нічого не запускай.
  `OWNER_ID` той самий, що для першого акаунта (учень може написати його в чат);
  api_id і api_hash — **нові**, з my.telegram.org з номера нового акаунта.
- Учень продовжує акаунт, який ще не доставлений, — працюй у папці цього акаунта.

## Як говорити з учнем

- Мовою учня: українською або російською, якщо він пише російською. Коротко, без слів
  «SSH», «venv», «крон», «сесія». Кажи «підключаюсь до сервера», «ставлю програму»,
  «вмикаю розклад».
- Один крок — одне повідомлення — одна дія учня. Далі сам перевір командою.
  Не питай «спрацювало?», якщо можеш перевірити сам.
- Кнопки оплати, паролі й коди учень натискає **сам**. Ти лише кажеш, куди натиснути.
- Якщо учень застряг на сайті — запропонуй подивитись його екран і підказати кнопку.
  Оплату і паролі він усе одно вводить сам.

## Секрети

Ніколи не проси і не повторюй у чаті, в логах, у `echo`, у `set -x`, у командному
рядку і в git:

| Що | Змінна | Як просити |
|---|---|---|
| Пароль root сервера | `VPS_ROOT_PASSWORD` | приховане поле |
| `api_id` | `TELEGRAM_API_ID` | приховане поле |
| `api_hash` | `TELEGRAM_API_HASH` | приховане поле |
| Номер акаунта розсилки | `TELEGRAM_PHONE` | приховане поле |
| Код із Telegram | `TELEGRAM_CODE` | приховане поле |
| Хмарний пароль | `TELEGRAM_2FA_PASSWORD` | приховане поле |

IP-адресу сервера, особистий числовий id (`OWNER_ID`) і назву агенції (`BRAND`)
учень може написати в чат: це не паролі.

Приховане поле кладе значення в змінну оточення твоєї оболонки. Далі ти передаєш
його на сервер **тільки як JSON у stdin** (команди нижче). Не підставляй секрет
в аргументи: їх видно у списку процесів. Не використовуй `sshpass -p`.

Якщо учень усе ж вставив секрет у чат — не цитуй його і не підтверджуй значенням.
Попроси ввести ще раз у приховане поле. Не копіюй секрет із тексту чату в команду.

Не роби `cat .env`, не роби `grep` по `.env` так, щоб рядок зі значенням потрапив
у вивід, не копіюй `.env` і `*.session` із сервера до себе, не коміть їх.
Перевіряти заповненість — лише `bash install.sh --status`.

## Кожного разу почни зі статусу

Розмова може обірватись. Не починай установку заново і не надсилай новий код у Telegram,
доки не побачиш статус. Команди підключення — у наступному розділі; далі:

```bash
vps 'cd /root/broadcast && bash install.sh --status'
```

Порожній каталог або `command not found` означає, що комплект ще не поставлено (крок 2).
Інакше дивись таблицю «Якщо розмова обірвалась» унизу і роби **лише** те, чого ще нема.

## Твій комп'ютер: доступ до сервера

Один раз постав клієнт (повторний запуск нічого не ламає):

```bash
sudo apt-get update -qq && sudo apt-get install -y -qq sshpass openssh-client
```

Далі в тій самій оболонці, після того як пароль уже в `VPS_ROOT_PASSWORD`, а IP учень
написав у чат (змінна `VPS_IP`):

```bash
export SSHPASS="$VPS_ROOT_PASSWORD"
vps() {
  sshpass -e ssh \
    -o StrictHostKeyChecking=accept-new \
    -o PreferredAuthentications=password \
    -o PubkeyAuthentication=no \
    -o NumberOfPasswordPrompts=1 \
    -o ConnectTimeout=20 \
    "root@${VPS_IP}" "$@"
}
vps 'echo ok'
```

Має відповісти `ok`. `sshpass -e` читає пароль зі змінної `SSHPASS`, не зі stdin,
тому далі в цю функцію можна передавати JSON з секретами.

Якщо пароль не підійшов — не кажи, який він був. Попроси ввести пароль ще раз
у приховане поле. Якщо ключ сервера змінився — спитай, чи учень перевстановив
сервер. Лише після «так» прибери старий ключ саме цієї адреси: `ssh-keygen -R "$VPS_IP"`,
і підключись знову.

## Одна програма з акаунтом за раз

Розсилка, вступ у групи і перевірки по черзі беруть замок `session.lock`. Усі команди
нижче, що відкривають акаунт, уже стоять за цим замком (`flock`). Не прибирай його.
`BUSY` у відповіді означає, що зараз іде розсилка або вступ у групи. Почекай 10–15 хвилин
і повтори. Не запускай нічого в обхід замка: два підключення одночасно рвуть розсилку.

## Крок 2. Поставити комплект

Повторний запуск безпечний: якщо каталог уже з git, буде оновлення, а не друга копія.
Чужий каталог без git не видаляй, якщо в ньому є `.env` або `*.session`.

```bash
vps 'bash -s' <<'EOF'
set -euo pipefail
export DEBIAN_FRONTEND=noninteractive
apt-get -o DPkg::Lock::Timeout=600 update -qq
apt-get -o DPkg::Lock::Timeout=600 install -y -qq git
if [ -d /root/broadcast/.git ]; then
  git -C /root/broadcast pull -q --ff-only || echo pull_skipped
elif [ ! -e /root/broadcast ]; then
  git clone -q https://github.com/dovguu20/tg-broadcast-kit /root/broadcast
elif [ -z "$(ls -A /root/broadcast)" ]; then
  rmdir /root/broadcast
  git clone -q https://github.com/dovguu20/tg-broadcast-kit /root/broadcast
else
  echo STOP directory_exists
  ls -A /root/broadcast
  exit 1
fi
bash /root/broadcast/install.sh
bash /root/broadcast/install.sh --status
EOF
```

Останній змістовний рядок установки: «встановлено в /root/broadcast».
Якщо apt зайнятий одразу після створення сервера — почекай хвилину і запусти ще раз.

Потім офлайн-перевірка комплекту (до Telegram не звертається):

```bash
vps 'cd /root/broadcast && venv/bin/python selfcheck.py'
```

Останній рядок має бути `ВСЕ ГАРАЗД`. Якщо ні — не йди далі, полагодь те, що впало.

## Крок 3. Акаунт, Premium і ключі — кілька стопів

Веди по одному повідомленню.

1. «Заведи окремий акаунт Telegram, не свій основний. З нього підуть оголошення,
   і його можуть обмежити — так буває з цим інструментом. Краще, щоб акаунту був
   уже місяць. Постав ім'я і фото агенції і задай ім'я користувача @...
   (Налаштування → Ім'я користувача): за ним ти потім напишеш акаунту «старт».»
   **Стоп**, доки учень не скаже, що акаунт є.
2. «Увімкни на ньому Telegram Premium. Без цього розсилка не запуститься.»
   **Стоп.**
3. «Увімкни хмарний пароль: Налаштування → Конфіденційність → Хмарний пароль.
   Запам'ятай його. У чат не пиши — я попрошу пізніше, коли будемо входити.»
   **Стоп.**
4. «Відкрий https://my.telegram.org саме з номера акаунта розсилки. Введи номер,
   потім код, який прийде в Telegram. Натисни API development tools. Назва додатка
   і коротке ім'я: broadcast. Платформа: Other. Створи. Побачиш два ключі: число
   і довгий рядок. У чат їх не копіюй.»
   Якщо сайт пише просто ERROR: вимкнути VPN, приватне вікно, мобільний інтернет
   замість Wi-Fi. На акаунт дозволений один ключ; якщо вже створювали — він відкриється.
   **Стоп.** Потім приховане поле: спочатку `TELEGRAM_API_ID` (лише цифри), потім
   `TELEGRAM_API_HASH` (32 символи).
5. «Зі свого основного акаунта, не з акаунта розсилки, напиши боту @userinfobot
   будь-що. Він відповість числом Id. Це число напиши мені сюди.»
   Це `OWNER_ID`. Якщо назву агенції теж хоче — це `BRAND`, теж можна в чат.

Записати ключі на сервер (значення у вивід не потрапляють):

```bash
python3 - <<'PY' | vps 'cd /root/broadcast && python3 apply_env.py'
import json, os, sys
keys = ("TELEGRAM_API_ID", "TELEGRAM_API_HASH", "OWNER_ID", "BRAND")
json.dump({k: os.environ.get(k, "") for k in keys}, sys.stdout)
PY
vps 'cd /root/broadcast && bash install.sh --status'
```

У статусі має бути `api_id=set`, `api_hash=set`, `owner_id=set`.
Рядок `invalid …` — це поле не записалось. Попроси лише його ще раз у приховане поле
(id власника — у чат) і запусти запис знову. Порожнє поле означає «не чіпати»,
тому повтор не стирає те, що вже записано.

Не змінюй паузи, список груп і розклад. Учень про це не просив.

## Крок 4. Вхід в акаунт розсилки

Не запускай `login_phone.py --login` і не викликай `getpass`: термінала немає,
обидва обірвуться.

Приховане поле, змінна `TELEGRAM_PHONE`, формат `+380…` (можна з пробілами).
Потім:

```bash
python3 - <<'PY' | vps 'cd /root/broadcast && venv/bin/python login_phone.py --send-code'
import json, os, sys
json.dump({"TELEGRAM_PHONE": os.environ.get("TELEGRAM_PHONE", "")}, sys.stdout)
PY
echo "exit:$?"
```

Дивись на JSON, поле `event` (сам JSON у чат учню не цитуй, якщо там раптом
щось зайве; номера і коду там бути не повинно):

| exit | event | Що робити |
|---|---|---|
| 0 | `code_sent` | Код надіслано. Скажи учню, куди дивитись (нижче), і **стоп**. |
| 0 | `code_already_pending` | Код уже просили. Не надсилай новий. Спитай, чи він прийшов. |
| 0 | `already_authorized` | Вхід уже є. Переходь до `check_account.py`. |
| 3 | `password_needed` | Код уже прийнято, бракує хмарного пароля. Див. нижче. |
| 2 | `rate_limited` | У JSON є `retry_after_seconds`. Чекай стільки і не повторюй раніше. |
| 2 | `invalid_phone_format` / `phone_missing` | Попроси номер ще раз у приховане поле. |
| 2 | `telegram_error` | Поле `error` — ім'я помилки. Не вигадуй новий код у циклі. |
| 2 | `unsupported_delivery` | Telegram хоче код у спосіб, який комплект не підтримує (наприклад, пошта). **Стоп**: скажи учню зробити скрін і написати Максу. Код більше не проси. |
| 2 | `connection_error` | Сервер не достукався до Telegram. Почекай хвилину і повтори той самий крок. |

Код виходу 3 сам по собі ще не означає `password_needed`: `sshpass` теж повертає 3,
коли не може підключитись. Дивись на `event` у JSON.

`delivery` = `SentCodeTypeApp` — скажи: «Код прийде в сам Telegram акаунта розсилки,
у службовий чат, не SMS. Як прийде — я попрошу його в окремому полі, в чат не пиши.»
Інший `delivery` — скажи той спосіб, який у JSON, без зайвих деталей.

**Стоп**, доки учень не отримає код. Приховане поле: `TELEGRAM_CODE`.

```bash
python3 - <<'PY' | vps 'cd /root/broadcast && venv/bin/python login_phone.py --sign-in'
import json, os, sys
body = {}
if os.environ.get("TELEGRAM_CODE"):
    body["TELEGRAM_CODE"] = os.environ["TELEGRAM_CODE"]
if os.environ.get("TELEGRAM_2FA_PASSWORD"):
    body["TELEGRAM_2FA_PASSWORD"] = os.environ["TELEGRAM_2FA_PASSWORD"]
json.dump(body, sys.stdout)
PY
echo "exit:$?"
```

- exit `0` і `event` `authorized` або `already_authorized` — вхід є.
- exit `3` і `password_needed` — код уже прийнято. **Не надсилай код знову.**
  Приховане поле: `TELEGRAM_2FA_PASSWORD`. Запусти `--sign-in` ще раз
  (у JSON тепер пароль; код можна не передавати).
- `telegram_error` і в полі `error` є `PhoneCodeInvalidError` — попроси код ще раз, той самий хеш ще живий.
- `PhoneCodeExpiredError` — скажи учню і лише тоді один раз `--send-code --resend`.
- `PasswordHashInvalidError` — хмарний пароль не той. Попроси ще раз. Новий код не надсилай.
- `session_missing` або `sign_in_not_ready` — коду ще не просили (або стан загубився): назад до `--send-code`.
- `code_missing` — у JSON не було коду. Попроси код у приховане поле ще раз.

Новий код (`--resend`) — тільки якщо учень каже, що код не прийшов, або код протух,
і немає `rate_limited`. Не більше одного разу поспіль.

Перевірка:

```bash
vps 'cd /root/broadcast && { flock -n -E 75 session.lock venv/bin/python check_account.py; [ $? != 75 ] || echo BUSY; }'
```

Потрібно `authorized=true` і `premium=True`. Ім'я користувача можна сказати учню.
`premium=False` — **стоп**: «На цьому акаунті немає Telegram Premium. Увімкни його
і напиши мені.» Потім перевір знову. Без Premium далі не йди.
`session=missing` або `Invalid TELEGRAM_API_ID` — повернись до кроку 3 чи 4, не вгадуй.

## Крок 5. Лист «старт» — стоп

Скажи: «Зі свого основного акаунта напиши акаунту розсилки будь-яке слово, наприклад
„старт“. Поки ти йому не напишеш, він не зможе надсилати тобі сповіщення.»

**Стоп.** Потім:

```bash
vps 'cd /root/broadcast && flock -w 1800 session.lock venv/bin/python wizard_check.py owner'; echo "exit:$?"
```

- `0` — лист видно, далі.
- `1` — ще не видно. Попроси перевірити, що пише саме акаунту розсилки, і повтори.
- `3` — перевірка не вдалась (зв'язок з Telegram). Почекай хвилину і повтори.
- `2` — у `OWNER_ID` стоїть id самого акаунта розсилки. Попроси особистий id від
  @userinfobot і запиши його знову через `apply_env.py`.

Поки на сервері `broadcast_running=yes`, цю перевірку не запускай: два підключення
одночасно рвуть розсилку. На етапі встановлення розсилки ще немає.

Скажи: «Зразки лежать у комплекті, файли texts/A.txt і texts/B.txt. Перепиши їх
своїми словами і підстав свою назву. Однаковий текст у десяти людей банять усіх.
З телефону, в акаунті розсилки, відкрий чат „Збережені“ і надішли собі спочатку
текст B, потім текст A — двома окремими повідомленнями. Більше нічого туди не шли:
у групи підуть два найновіші повідомлення, що б там не лежало.»

**Стоп.** Коли учень напише, що надіслав:

```bash
vps 'cd /root/broadcast && flock -w 1800 session.lock venv/bin/python wizard_check.py saved'
```

Покажи йому початки двох текстів і спитай: «Це твої оголошення, спочатку B, потім A?»
**Стоп**, доки не скаже «так». Якщо ні — хай надішле правильні, і перевір знову.

## Крок 7. Старі чати і вступ у групи

Лише після «так» на тексти. Спочатку запам'ятати вже наявні листи, щоб про старих співрозмовників
не прийшли сповіщення «новий лід» (ліду розсилка нічого не пише):

```bash
vps 'cd /root/broadcast && flock -w 1800 session.lock venv/bin/python lead_reply.py --seed'
```

Далі вступ у групи **тільки** через `join_step.sh`. Він сам робить паузу, коли
Telegram просить почекати, прибирає себе з розкладу, коли список пройдено,
запам'ятовує старі чати, якщо це ще не зроблено, вмикає 5 завдань розсилки
і пише учню «✅ Акаунт N (…) вступив у групи, розсилка увімкнена».

Не збирай розклад розсилки руками і не запускай `install.sh --cron` зараз.
Інакше пости підуть до того, як акаунт увійде в групи, або не підуть узагалі,
якщо ти не повернешся за кілька годин.

```bash
vps 'bash -s' <<'EOF'
set -euo pipefail
chmod +x /root/broadcast/join_step.sh
cd /root/broadcast && { flock -w 1800 session.lock venv/bin/python wizard_check.py joining || echo "ALERT_FAILED"; }
{ crontab -l 2>/dev/null | grep -vF "/root/broadcast/join_step.sh # tg-join-temp" || true
  echo "7 * * * * bash /root/broadcast/join_step.sh # tg-join-temp"
} | crontab -
cd /root/broadcast && nohup bash join_step.sh >/dev/null 2>&1 &
sleep 1
crontab -l | grep tg-join-temp
tail -n 5 /root/broadcast/join.log || true
EOF
```

`ALERT_FAILED` — повідомлення учню в особисті не дійшло. Вступ у групи все одно запущено;
перевір `OWNER_ID` (команда `wizard_check.py owner` вище) і що учень писав акаунту розсилки.
Поки не полагодиш — не кажи учню, що 🟢 прийшло.

Повторний запуск не дублює рядок розкладу. Другий `join_step.sh` одразу виходить,
якщо перший ще працює.

Скажи учню: «Тобі в Telegram прийшло 🟢 — сповіщення доходять. Зараз акаунт сам вступає в групи.
Це близько чотирьох годин, можна відійти. Коли закінчить, прийде ✅ — розсилка увімкнена.
Далі пости йдуть самі, кожні дві години. Комп'ютер можна закрити.»

Не чекай ці години в чаті. Не запускай `broadcast.py`.

«заявка на модерацію» і «нема такої групи» в `join.log` — нормально.
Якщо в лозі «Вступ у групи зупинено» — нічого не видаляй і не запускай вступ
знову сьогодні: `join_step.sh` уже поставив паузу на добу.

## Крок 8. Перевірка

Коли учень повернеться або попросить подивитись, як справи. Нічого не надсилає в групи.

1. Розклад і прогрес:

```bash
vps 'cd /root/broadcast && bash install.sh --status'
vps 'tail -n 20 /root/broadcast/join.log || true'
```

2. Поки вступ не закінчився (`join_complete=no`, `join_cron=yes`): скажи, скільки
   груп уже пройдено (`join_done` із `join_total`), і що решта йде сама.
   `broadcast_cron=0` у цей час — правильно. Не вмикай розсилку вручну.

3. Коли `join_complete=yes`: рядка `# tg-join-temp` вже немає (`join_cron=no`),
   а `broadcast_cron=5`. Якщо список пройдено, а `broadcast_cron=0` (обірвалось
   між кроками) — лише тоді:

```bash
vps 'cd /root/broadcast && { [ -f leads_seen.json ] || flock -w 1800 session.lock venv/bin/python lead_reply.py --seed; } && bash install.sh --cron'
```

4. Акаунт досі в порядку: `check_account.py` → `authorized=true`, `premium=True`.

5. Офлайн-перевірка, якщо розсилка зараз не йде (`broadcast_running=no`):

```bash
vps 'cd /root/broadcast && venv/bin/python selfcheck.py'
```

Останній рядок: `ВСЕ ГАРАЗД`.

6. Суха перевірка. У команді обов'язково є `--dry`. Вона нічого не надсилає,
   триває близько двох хвилин:

```bash
vps 'cd /root/broadcast && { flock -n -E 75 session.lock venv/bin/python broadcast.py --dry; [ $? != 75 ] || echo BUSY; }; tail -n 5 cron.log'
```

У лозі шукай рядок `DRY | варіанти: … | груп знайдено: N`.
Покажи учню початки двох текстів і спитай, чи це його оголошення.
«не знайдено» для окремих груп — нормально. Якщо таких більше десяти — скажи,
що частина списку застаріла, і йди далі.

7. Скажи простими словами:
   - перший пост — за розкладом, протягом 2 годин; прогін триває близько 50 хвилин;
   - у особисті прийдуть «🔔 Новий лід…», «⚠️ …» або «⛔️ …»; що робити — таблиця нижче;
   - у «Збережені» більше нічого не слати, крім нових текстів оголошень;
   - на сервер самому не заходити.
8. Якщо на сервері готових акаунтів менше трьох — одразу переходь до наступного акаунта
   (розділ «Кілька акаунтів на одному сервері»): нова папка, від кроку 2.

## Живий пробний пост — не частина встановлення

Не запускай `broadcast.py` без `--dry`, доки встановлення не закінчене і учень
**окремим повідомленням після сухої перевірки** не напише «так, надсилай».
За замовчуванням пробний пост не потрібен: перші оголошення підуть за розкладом.

Якщо такого повідомлення немає — команди нижче не існує. Якщо є і ти перепитав
«це надішле справжнє оголошення в три групи» і учень знову підтвердив — тоді
підстав три групи зі списку, не весь список і не вигадуй нові:

```bash
vps "cd /root/broadcast && TELEGRAM_START_JITTER=0 TELEGRAM_TARGET_GROUPS='@одна,@друга,@третя' venv/bin/python broadcast.py; tail -n 6 cron.log"
```

`@одна,@друга,@третя` заміни на три справжні назви зі списку комплекту.
Не друкуй учню весь список. Жодного `OK` із трьох — не гони все коло груп.
«Немає прав писати» або «вікно групи» для окремих груп — нормально.

## Якщо розмова обірвалась

| Що у `--status` | Що робити |
|---|---|
| `broadcast_running=yes` | **спершу це**: нічого з цим акаунтом не запускай, почекай кінця прогону (до 50 хв) |
| комплект не клоновано | крок 2 |
| `api_id=empty` або `invalid` | крок 3, не чіпай вхід |
| `session=missing` і `login_pending=no` | крок 4, `--send-code` |
| `login_stage=code` | не надсилай новий код; спитай учня; `--sign-in` або один `--resend` |
| `login_stage=password` | `--sign-in` лише з хмарним паролем |
| `check_account.py` показує `premium=False` | стоп, учень вмикає Premium |
| лист «старт» ще не видно | крок 5 |
| тексти учень не підтвердив | крок 6, навіть якщо вступ уже йде |
| тексти підтверджено, `join_cron=no`, `join_complete=no` | крок 7 |
| `join_cron=yes` | не перевстановлюй; скажи прогрес `join_done` / `join_total` |
| `join_complete=yes` і `broadcast_cron=5` | крок 8 |
| `join_complete=yes` і `broadcast_cron=0` | одне відновлення з кроку 8, пункт 3 |

## Якщо щось пішло не так

| Симптом | Що робити |
|---|---|
| `authorized=false` після входу | повторити крок 4. Файл сесії видаляй лише якщо вхід так і не вийшов: `rm -f /root/broadcast/sender.session*` — і одразу новий `--send-code`, бо старий код без цього файла непридатний |
| `premium=False` | учень вмикає Premium, потім знову `check_account.py` |
| `database is locked` | іде інший процес із цією сесією; почекати |
| `rate_limited` | чекати `retry_after_seconds`, не частіше |
| «Вступ у групи зупинено» | нічого не робити добу; `join_step.sh` продовжить сам |
| «⚠️ @SpamBot: обмеження» | 3–7 днів не постити; учень пише @SpamBot, що це помилка |
| «⚠️ Telegram Premium закінчився» | поновити Premium |
| «⛔️ Розсилка стоїть» або «УПАЛА» | `tail -n 30 /root/broadcast/cron.log`; не запускай другий прогін, поки перший живий |
| тривоги не приходять | `OWNER_ID` має бути id особистого акаунта; учень пише акаунту розсилки «старт»; у «Збережених» не повинні лежати тексти тривог |

Паузи, список груп і п'ять рядків розкладу не змінюй. Вони такі самі, як у робочого комплекту.

# SETUP.md — інструкція для AI-агента

Ти встановлюєш автоматичну розсилку оголошень у Telegram-групи для людини, яка
**не програміст**. Усе, що тут написано, — для тебе. Людині кажи тільки те, що їй
треба зробити руками, простими словами, по одному кроку за раз.

## Як поводитись

- Говори мовою людини (українська або російська), коротко, без технічних термінів.
  Не кажи «SSH», «venv», «крон» — кажи «підключаюсь до сервера», «ставлю програму»,
  «вмикаю розклад».
- Один крок — одне повідомлення — одна дія від людини. Після кожного кроку сам
  перевір результат командою; не питай людину «спрацювало?», якщо можеш перевірити сам.
- **Ніколи не проси і не приймай у чат**: пароль від сервера, пароль Telegram, код
  із Telegram, дані картки, вміст файлів `.env` і `*.session`. Якщо людина сама
  вставила щось таке в чат — не повторюй це у відповіді й іди далі.
- Не виводь у чат значення з `.env`. Перевіряй, що поля заповнені, не показуючи їх:
  `grep -c '^TELEGRAM_API_ID=.\+' .env`.
- **Допомога з екраном.** Якщо людина застрягла на сайті (хостер, my.telegram.org,
  GitHub) або не знаходить кнопку — запропонуй подивитись її екран чи браузер: у тебе
  можуть бути інструменти перегляду екрана або розширення для Chrome. Попроси дозвіл
  і дивись. Кнопки оплати, введення паролів і кодів людина натискає **сама**, ти лише
  показуєш куди.
- Нічого не змінюй у налаштуваннях комплекту (паузи, список груп, розклад), якщо
  людина про це не просила. Комплект має працювати рівно так, як у автора.
- Поки іде прогін розсилки на сервері, не запускай нічого іншого з Telegram-акаунтом:
  дві програми на одній сесії одночасно рвуть з'єднання. Перевірка:
  `pgrep -af '[b]roadcast.py'` — якщо є процес, почекай (квадратні дужки — щоб pgrep не зловив сам себе).
- Не копіюй файли `.session` і `.env` із сервера нікуди.

## Що потрібно від людини (людина НЕ дає це наперед — запитай усе разом, одним повідомленням, і поясни, де взяти кожне)

1. IP-адреса сервера (Ubuntu 22.04 або 24.04, доступ root). Пароль НЕ питай — людина
   введе його сама, коли попросить система.
2. `api_id` (число) і `api_hash` (32 символи) з https://my.telegram.org → «API development tools».
3. Її особистий Telegram id (число; бот @userinfobot відповідає ним на будь-яке повідомлення).
   Це має бути **інший** акаунт, не той, з якого буде розсилка. І з цього особистого акаунта
   людина має **один раз написати будь-що акаунту розсилки** (наприклад «старт») — інакше
   Telegram не дасть акаунту розсилки надіслати їй сповіщення.
Комплект людина не скачує: репозиторій публічний (https://github.com/dovguu20/tg-broadcast-kit). Щоб читати файли,
клонуй його собі сам (`git clone https://github.com/dovguu20/tg-broadcast-kit`) або качай ZIP
(https://github.com/dovguu20/tg-broadcast-kit/archive/refs/heads/main.zip). На сервер він ставиться прямо з GitHub (крок 2).

Telegram-акаунт для розсилки має бути з **Telegram Premium** і бажано не новішим за
місяць. Якщо Premium нема — розсилка не запуститься, це перевіряється на кроці 5.

## Кроки

### 1. Доступ до сервера
- Перевір, чи є ключ: `ls ~/.ssh/id_ed25519.pub`. Нема — `ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519`.
- Скопіюй ключ на сервер. Це єдина команда, де людина вводить пароль, і вводить **сама**
  у своєму терміналі (панель Terminal або окреме вікно терміналу), не через твій bash:
  - macOS/Linux: `ssh-copy-id root@IP`
  - Windows (PowerShell): `type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@IP "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"`
  Скажи людині: «з'явиться питання yes/no — напиши yes; потім попросить пароль із
  листа від хостера — введи його, символи не показуються, це нормально».
- Перевірка: `ssh -o BatchMode=yes root@IP echo ok` → `ok`.

### 2. Завантажити комплект на сервер
`ssh root@IP "apt-get update -qq && apt-get install -y -qq git && git clone https://github.com/dovguu20/tg-broadcast-kit /root/broadcast"`
Перевірка: `ssh root@IP ls /root/broadcast` показує `broadcast.py`, `install.sh`, `.env.example`.

### 3. Встановити
`ssh root@IP bash /root/broadcast/install.sh`
Триває 1–3 хвилини. Останній рядок має бути «встановлено в /root/broadcast».
Якщо впало на apt — повтори через хвилину (хостер ще добиває систему після створення).

### 4. Заповнити налаштування
У файлі `/root/broadcast/.env` заповни рівно три поля значеннями від людини:
`TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `OWNER_ID`. За бажання `BRAND=` назва агенції.
Роби це через `sed -i` або python на сервері, значення в чат не повторюй.
Перевірка: `ssh root@IP "cd /root/broadcast && grep -c '^TELEGRAM_API_ID=.\+\|^TELEGRAM_API_HASH=.\{32\}$\|^OWNER_ID=[0-9]\+' .env"` → `3`.

### 5. Вхід у Telegram (інтерактивно, у терміналі людини)
Скажи людині відкрити термінал і вставити:
`ssh -t root@IP "cd /root/broadcast && venv/bin/python login_phone.py --login"`
Поясни наперед, що буде: «попросить номер телефону акаунта для розсилки у форматі
+380…, потім код, який прийде у сам Telegram (не SMS), потім хмарний пароль, якщо він
увімкнений. Символи при введенні не показуються». Якщо програма пише `rate_limited` —
Telegram просить почекати стільки секунд, скільки вказано; не повторюй вхід частіше.
Перевірка: `ssh root@IP "cd /root/broadcast && venv/bin/python check_account.py"` →
`authorized=true username=@... premium=True`.
Тут же нагадай: «зі свого особистого акаунта напиши акаунту розсилки слово "старт"» —
і перевір, що це зроблено (у кроці 10 цей діалог буде серед запам'ятованих).
`premium=False` → зупинись і скажи людині ввімкнути Telegram Premium на цьому акаунті,
потім повтори перевірку. Без Premium далі йти нема сенсу.

### 6. Тексти оголошень
Поясни людині (див. `texts/ЯК-КОРИСТУВАТИСЬ.md`): переписати два зразки своїми словами
і надіслати собі у «Збережені» (Saved Messages) з телефону — спочатку B, потім A, двома
окремими повідомленнями. Більше нічого собі у «Збережені» не слати: розсилка бере два
найновіші.
Поки людина пише тексти — переходь до кроку 7, він довгий.

### 7. Вступ у групи (≈5 годин, автоматично)
Акаунт має бути учасником кожної з 81 групи. Вступ іде партіями по 20 з паузами, щоб
Telegram не вважав це спамом. Постав тимчасовий розклад на сервері:
```
( crontab -l 2>/dev/null; echo "7 * * * * cd /root/broadcast && flock -n /root/broadcast/join.lock venv/bin/python join_groups.py 20 >> join.log 2>&1 # tg-join-temp" ) | crontab -
```
і одразу запусти першу партію руками у фоні (той самий flock — щоб дві партії не йшли одночасно):
`ssh root@IP "cd /root/broadcast && nohup flock -n /root/broadcast/join.lock venv/bin/python join_groups.py 20 >> join.log 2>&1 &"`.
Скажи людині, що це триватиме кілька годин і можна відійти.
Перевірка готовності: `wc -l < /root/broadcast/joined_done.txt` → 81 і в `join.log`
є «СПИСОК ПРОЙДЕНО ПОВНІСТЮ». Тоді прибери тимчасовий розклад:
`crontab -l | grep -v "# tg-join-temp" | crontab -`.
Якщо в `join.log` є «Вступ у групи зупинено» (FloodWait/PeerFlood) — нічого не роби добу,
розклад сам продовжить наступної години; якщо повторюється — почекати день.
«заявка на модерацію» і «нема такої групи» — нормально, такі групи просто не отримають постів.

### 8. Суха перевірка (нічого не надсилає)
Коли тексти у «Збережених» і групи пройдені:
`ssh root@IP "cd /root/broadcast && venv/bin/python broadcast.py --dry; tail -3 cron.log"`
(триває ~2 хвилини: між групами пауза, щоб не впертись у ліміт Telegram)
У лозі має бути рядок `DRY | варіанти: id=... «початок тексту A», id=... «початок тексту B» | груп знайдено: N`.
Покажи людині початки двох текстів і спитай: «це твої оголошення, A і B?». Якщо ні —
крок 6. «не знайдено» — такої групи або юзернейму більше не існує; це не про членство
(чи акаунт у групі, видно лише на реальній відправці, крок 9). Якщо не знайдено більше
10 — список застарів, скажи про це людині й іди далі.

### 9. Пробний прогін на 3 групи (надсилає по-справжньому)
```
ssh root@IP "cd /root/broadcast && TELEGRAM_START_JITTER=0 TELEGRAM_TARGET_GROUPS='@Adult_platform,@Adults_play_Board,@Advertising_BF' venv/bin/python broadcast.py; tail -6 cron.log"
```
Очікуй `OK (A) -> @...` або `OK (B) -> @...` хоча б для однієї групи і рядок `ФІНІШ`
(літера чергується з кожним запуском). «Немає прав писати»
або «FloodWait … вікно групи» для окремих груп — нормально (адміни групи або її добове
вікно), це не помилка комплекту. Жодного OK із трьох — повтори з іншими трьома групами
зі списку; знову нуль — див. «Якщо щось пішло не так».

### 10. Запам'ятати існуючі чати
`ssh root@IP "cd /root/broadcast && venv/bin/python lead_reply.py --seed"` → «запам'ятовано N діалогів».
Без цього авто-відповідь пішла б усім старим співрозмовникам акаунта.

### 11. Увімкнути автоматику
`ssh root@IP bash /root/broadcast/install.sh --cron` → показує 5 рядків розкладу.
Що вони роблять: розсилка кожні 2 години (о :00 парних годин за Києвом); авто-відповідь
новим лідам кожні 5 хв; сторож щогодини; перевірка @SpamBot щоночі 01:45; звіт лідів
щопонеділка 11:05. Усі сповіщення приходять людині в ЛС від акаунта розсилки.

### 12. Фініш
Скажи людині простими словами:
- коли перший прогін (найближча парна година за Києвом) і що він триває ~50 хвилин;
- як перевірити: «напиши мені "покажи лог" — я подивлюсь»; команда для тебе:
  `ssh root@IP "grep ФІНІШ /root/broadcast/cron.log | tail -3"`;
- що прийде в ЛС: «🔔 Новий лід…», «⚠️ …» або «⛔️ …» — і що робити (таблиця в README);
- правило «Збережених»: нічого собі не слати, крім оголошень;
- не заходити на сервер і не чіпати файли без тебе.

## Якщо щось пішло не так

| Симптом | Причина | Що робити |
|---|---|---|
| `authorized=false` після входу | код введено невірно або сесія не збереглась | повторити крок 5; перед цим `rm -f sender.session*` |
| `premium=False` | нема Telegram Premium | людина вмикає Premium; повторити перевірку |
| `database is locked` | дві програми відкрили одну сесію | `pgrep -af broadcast.py`, почекати закінчення прогону, повторити |
| `FloodWaitError` / `rate_limited` при вході | забагато спроб | чекати вказані секунди, не повторювати частіше |
| `PeerFlood` при вступі | Telegram вважає дії спамом | нічого не робити добу; потім продовжити |
| нуль OK у пробному прогоні, всюди «Немає прав» | акаунт не в групах або новий акаунт обмежений | перевірити `joined_done.txt`; написати @SpamBot /start з акаунта, прочитати відповідь |
| «⚠️ @SpamBot: обмеження» | тимчасовий спам-бан | не постити 3–7 днів; людина пише @SpamBot, що це помилка; розсилка сама продовжить, коли бан знімуть |
| «⛔️ Розсилка стоїть» | прогони не завершуються | `tail -30 cron.log`; шукати Traceback; `venv/bin/python -c "import broadcast"` має мовчати |
| тривоги не приходять | `OWNER_ID` порожній, або це id самого акаунта, або власник ще не писав акаунту розсилки | виправити `.env` (id ОСОБИСТОГО акаунта); власник пише акаунту розсилки «старт»; потім `broadcast.py --dry` і переконатись, що два варіанти — це оголошення, а не тексти тривог (якщо тривоги впали у «Збережені» — людина видаляє їх звідти) |

Повна офлайн-перевірка комплекту (без Telegram): `venv/bin/python selfcheck.py` → «ВСЕ ГАРАЗД».
